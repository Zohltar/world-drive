# Block 8 biome R9 — finite diagnostic pilot and full-game experiment

Continuation of R8, on the existing candidate / draft PR #14 only. No biome merge,
new renderer consumer, tree palette, density retune or stable-main movement.

## Scope

R8 already connects the diagnostic observer to the actual public route lifecycle.
R9 does not rewrite it. Its new packager builds a portable public/ directory from
exactly the three source-polygon tiles and three manifest pages verified by R8 at
`c89e094e8120de30664d4211a41aae6b75fd7d31`, exact-head run `35287102949` PASS.
That result certifies R8 only, not this R9 experiment.

The packager requires the exact whitelist, sizes and SHA-256 of every input file,
including the catalog directory and attribution. Missing, extra, symlinked or
corrupt files are rejected before writing output. Existing output is never
replaced. Geometry/gzip are copied unchanged; there is no geography inference,
network call or heavy geospatial dependency in the packager. The ZIP is reproducible.

The launcher embeds the trusted finite directory as static JavaScript and delegates
to the existing R8 diagnostic start/stop API. Importing the module is inert; only
an explicit start enables the observer. The directory is trusted packaged input,
NOT a signed or dynamically authenticated worldwide root. Its one-time module
parse/configuration copying remains main-thread work and is not a zero-cost claim.

Three pilot tiles cover limited regions around Laguna Seca and the Nordschleife.
They do not cover Manic-2 → Manic-5 or the world. The observer still samples at most
four chunks, not the entire visible forest. Missing data remains unavailable;
no source result receives planting/elevation/transition authority.

## Reproduction

```sh
python tools/biomes/package-diagnostic-pilot.py --pilot INPUT/pilot --output OUTPUT
python qa/qa-block8-biome-pilot-r9.py --pilot INPUT/pilot
python qa/qa-block8-biome-fullgame-r9.py --pilot INPUT/pilot --output FULLGAME_OUTPUT
```

Input is pilot/ in the verified R8 gameplay artifact, or the identical folder
regenerated by the maintained R8 browser test. Local packager tests require Python
and Node; full-game testing also requires the project's npm dependencies and the
existing CI Playwright/Chromium environment. The full-game test runs the actual
`npm run build`, then serves the real dist/index.html, not a substitute harness.

For a human diagnostic pilot: copy the ZIP's public/ folder into the candidate
checkout before `npm run dev` (or before the production build). Choose a circuit
through the existing menu, start driving, and explicitly enable from DevTools:

```js
await (await import('/local-data/biomes/pilot-r9/start.mjs')).start()
WorldDriveDiagnostics.forest.biomes.snapshot()
WorldDriveFramePacing()
// stop and terminate the observer's work:
WorldDriveDiagnostics.forest.biomes.stop()
```

This is not a visual biome release. No different trees should be expected.
Do not request a human PASS until the relevant automated pilot checks are green.

## Full-game gates and measurement limitations

The automation uses the complete production Three.js game and its real route,
terrain, rendering, forest and physics implementations. Actual DOM preset and
jump controls drive the authored circuit route selections; no game module or
internal service is replaced. Worker construction/termination is instrumented,
not emulated. The default must make no pilot data request or biome Worker.

Upstream network services are deliberately controlled to make CI reproducible:
a short SYNTHETIC routing response boots the default chooser and is excluded from
geographic evidence. External imagery/elevation/OSM return HTTP 503; the unchanged
application fallback paths run. This is NOT a validation of real terrain, actual
Manic routing, hydrography availability or current vegetation.

The automated render target is headless software WebGL at 960 x 540. It records
the actual unmasked renderer. OFF / ON / OFF parked windows on each circuit record
rAF distributions and the existing WorldDriveFramePacing snapshots. Teleports to
25%/75% follow the parked measurements. Current/forward resolved/noData/unavailable
counts, receipt/plan/round-trip costs, store limits and Worker termination are
retained with screenshots and console failures in the exact-head artifact.

Functional assertions require active rendering, exact authored route point counts,
ready current geography, no placement authority, bounded storage and no restarted
I/O after stop. Missing readiness or a game page exception fails the experiment.
No performance threshold is weakened because CI is software-rendered: there is
no GPU/FPS certification threshold in this experiment at all. Report timing as
observations, not proof of 60/144 FPS, high-speed continuity or statistical absence
of regression. Real hardware and a real long-road dataset remain subsequent gates.
